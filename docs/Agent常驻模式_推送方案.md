# 🚨 Agent 常驻模式 — 持续推送内容方案

> **视角**：应急响应专家
> **目标**：设计 Agent 在 `--daemon` 模式下持续推送的内容类型、策略、展示方案
> **核心理念**：信息密度合理——不遗漏关键预警，不淹没分析人员

---

## 一、推送内容规划

### 1.1 内容分类总表

| 类别 | 推送内容 | 优先级 | 数据量级 | 推送通道 |
|------|---------|:------:|:--------:|:--------:|
| **安全事件** | 进程创建/终止、远线程注入、DLL 加载 | P0 紧急 | 5-50 条/秒 | 🚨 实时 WebSocket |
| **网络事件** | 新建连接、断连、DNS 解析、监听端口 | P0 紧急 | 2-20 条/秒 | 🚨 实时 WebSocket |
| **文件事件** | 文件创建/修改/删除（敏感目录） | P1 常规 | 1-10 条/秒 | 📦 批量推送 |
| **用户事件** | 登录/登出、用户创建、权限变更 | P1 常规 | 0.1-1 条/秒 | 📦 批量推送 |
| **状态变更** | 服务启停、安全产品状态、注册表变更 | P2 汇总 | 0.01-0.1 条/秒 | 📊 周期汇总 |
| **资源监控** | CPU/内存/磁盘、进程资源消耗 | P2 汇总 | 1 条/60 秒 | 📊 周期汇总 |
| **心跳** | Agent 存活、采集器健康状态 | - | 1 条/30 秒 | 🔵 独立通道 |

## 二、推送策略设计

### 2.1 三通道推送模型

```
┌──────────────────────────────────────────────────────────────┐
│                       Agent 事件源                            │
│  进程事件  网络事件  文件事件  用户事件  状态变更  资源  心跳   │
└──────────┬──────────┬──────────┬──────────────────────────────┘
           │          │          │
     ┌─────▼──────┐ ┌─▼──────┐ ┌▼───────────┐
     │ 🚨 紧急通道 │ │📦 常规 │ │📊 汇总通道  │
     │            │ │ 批量   │ │            │
     │ WebSocket  │ │ HTTP   │ │ HTTP       │
     │ 实时推送    │ │ 5-30s  │ │ 5-60min    │
     │            │ │ 一批   │ │ 摘要        │
     └─────┬──────┘ └───┬────┘ └─────┬──────┘
           │            │            │
           ▼            ▼            ▼
     ┌─────────────────────────────────────┐
     │           平台后端接收                 │
     │  AlertEngine  → 告警                 │
     │  ProcessEventConsumer → 入库         │
     │  摘要处理器 → 统计更新                │
     └─────────────────────────────────────┘
```

### 2.2 通道参数

| 通道 | 触发条件 | 推送频率 | 协议 | 数据格式 |
|:----:|---------|:--------:|:----:|---------|
| 🚨 **紧急** | 规则命中 critical/high | **即时**（<1s） | WebSocket | 单条事件 |
| 📦 **常规** | 缓冲区满 or 超时 | **5-30s** | HTTP POST | 批量数组 |
| 📊 **汇总** | 定时器触发 | **5-60min** | HTTP POST | 聚合统计 |
| 🔵 **心跳** | 定时器触发 | **30s** | HTTP POST | 状态摘要 |

### 2.3 内容去重与合并规则

```
规则 1：同类型 + 同进程 + 5分钟内 → 合并为 1 条 count++
  例: certutil 在 3 分钟内被触发了 5 次
  → 不推送 5 条，推送 1 条 {count:5, first_seen:..., last_seen:...}

规则 2：突发抑制（Burst Suppression）
  例: 同一规则 1 分钟内触发 > 50 次
  → 第 1-50 条正常计数，第 51 条起生成 "突发告警摘要"
  → 摘要内容: "certutil 下载在 1 分钟内触发了 127 次"

规则 3：已知白名单静默
  例: 微软签名的 svchost.exe 创建网络连接
  → 如果进程有有效微软签名，连接目标为已知微软 IP 段
  → 不产生告警（仅记录日志）

规则 4：相同告警聚合（后端 AlertEngine 已实现）
  5 分钟内同一 host_id + rule_name → count+1，不新建告警

规则 5：事件分级推送
  critical/high 事件 → 即时 WebSocket 推送（紧急通道）
  medium/low 事件 → 等待批量窗口（常规通道），减少每秒推送量
```

### 2.4 带宽与资源预算

| 指标 | 预算 | 说明 |
|------|:----:|------|
| 单事件体积 | ~200-500 bytes | JSON 序列化后 |
| 紧急通道峰值 | 10 条/秒 | 约 5KB/s |
| 常规通道峰值 | 50 条/5 秒 | 约 25KB/5s |
| 汇总通道 | 1 条/5min | 约 2KB |
| 心跳 | 1 条/30s | 约 500 bytes |
| **总计带宽** | **~10KB/s** | 普通企业带宽完全可承受 |

### 3.2 核心功能模块

| 模块 | 功能 | 数据源 |
|------|------|--------|
| **事件流**（左侧） | 实时滚动的原始事件日志，按严重度着色，点击查看详情 | WebSocket `/ws/events` |
| **统计卡片** | 今日事件总量、紧急告警数、在线主机、规则命中数 | `GET /api/alerts/stats` |
| **实时事件速率** | ECharts 面积图，展示过去 5m/15m/30m 的事件吞吐 | `GET /api/alerts/stats/trend` |
| **最近告警** | 最新的未处理告警列表，点击跳转告警中心 | WebSocket + `GET /api/alerts` |
| **主机状态** | 所有主机在线/离线状态，Agent 版本，心跳时间 | `GET /api/agents/online-status` |

### 3.3 交互说明

1. **事件流**自动滚动（最新事件在最上），用户悬停暂停滚动
2. 点击事件行 → 展开详情卡片（进程名、命令行、哈希、签名等）
3. 严重度配色：🔴 CRITICAL / 🟡 HIGH / 🔵 MEDIUM / ⚪ LOW
4. 紧急事件到达时：**声音提醒** + **浏览器通知** + **事件流红色闪烁**
