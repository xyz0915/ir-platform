# 个人应急响应平台 — 产品需求文档（PRD）

## 1. 产品概述

### 1.1 项目信息

| 项目 | 内容 |
|------|------|
| Language | 中文 |
| Programming Language | Python（后端）+ Vue 3（前端） |
| Project Name | personal_ir_platform |
| 原始需求复述 | 做一个个人应急响应平台工具，需要有 Web 界面，数据留存在本地，轻量化。包含 Web 登录首页、案件管理、主机管理、Agent 下载页、JSON 导入页、报告查看与导出等基础功能；Agent 采集覆盖主机基础信息、用户、进程、服务、启动项、网络、文件、注册表、日志、安全软件、浏览器痕迹、USB 痕迹、远程控制痕迹、持久化痕迹、IOC 能力、时间线等；平台具备自动分析能力（主机画像、异常识别、攻击时间线、风险等级、处置建议）；报告功能覆盖案件信息、异常发现、IOC 命中、时间线、持久化项、可疑外联、结论与处置建议。本地部署，SQLite + JSON 存储，不依赖云服务，适配 Windows 与 Linux。 |

> **技术选型说明**：原需求未指定技术栈，考虑到「本地部署、轻量化、单文件 Agent、适配 Windows/Linux」的要求，推荐后端使用 Python（Flask/FastAPI 轻量框架，生态丰富便于取证分析），前端使用 Vue 3 + Element Plus（组件丰富、上手快）。Agent 采集端使用 Python 打包为单文件可执行程序（PyInstaller），或使用 Go 编译单文件以获得更小的分发体积。最终技术栈以架构师评估为准。

### 1.2 产品定位

**个人应急响应平台**是一款面向安全工程师的本地化轻量级应急响应工具。它通过单文件 Agent 一键采集主机取证数据，导入平台后自动完成威胁分析、画像生成与时间线梳理，最终输出结构化应急响应报告。整个流程不依赖任何云服务，数据完全留存于本地，满足应急响应场景下「快速取证、离线分析、数据保密」的核心诉求。

### 1.3 目标用户

| 用户角色 | 典型场景 | 核心诉求 |
|----------|----------|----------|
| 安全工程师 / 应急响应人员 | 接到应急事件后需快速取证分析 | 快速采集、自动分析、一键报告 |
| SOC 分析师 | 日常威胁狩猎、可疑主机排查 | 结构化数据、IOC 匹配、时间线还原 |
| 企业 IT 管理员 | 内网主机异常排查 | 操作简单、不依赖云、数据不外泄 |
| 安全顾问 / 外部支援人员 | 客户现场应急响应 | 单文件分发、离线运行、可移植 |

### 1.4 核心价值

1. **快速取证**：单文件 Agent 一键采集 16 大类取证数据，无需安装、即拷即用
2. **自动分析**：导入 JSON 即自动完成主机画像、异常识别、时间线还原与风险评级
3. **数据自主**：全程本地部署，SQLite + JSON 存储，数据不离开用户环境
4. **一键报告**：结构化应急响应报告，支持导出，便于汇报与留存

## 4. 功能模块说明

### 4.1 平台基础功能

#### 4.1.1 Web 登录首页
- 账号密码登录，默认提供初始管理员账号（首次登录强制修改密码）
- 登录后进入仪表盘首页，展示全局统计概览
- 会话管理，超时自动登出

#### 4.1.2 案件管理
- 案件 CRUD：创建、查看、编辑、删除案件
- 案件信息字段：案件编号（自动生成）、案件名称、事件类型（勒索病毒/挖矿/后门/APT/其他）、发生时间、发现时间、描述、状态（进行中/已关闭）、关联主机列表
- 案件列表支持搜索与筛选

#### 4.1.3 主机管理
- 主机列表展示所有已采集主机，关联案件信息
- 主机详情页展示主机画像与完整采集数据
- 支持按案件、风险等级、系统类型筛选
- 风险等级用颜色标识（红/橙/黄/绿）

#### 4.1.4 Agent 下载页
- 提供 Windows 与 Linux 版本单文件 Agent 下载
- Agent 为单文件可执行程序，无需安装，即拷即用
- P2：支持配置采集项后下载定制化 Agent

#### 4.1.5 JSON 导入页
- 拖拽或选择文件上传 Agent 采集的 JSON
- 导入时选择关联案件与主机（或自动创建主机记录）
- 导入后自动触发分析流程，展示分析进度
- 支持校验 JSON 格式与完整性

#### 4.1.6 报告查看与导出
- 报告页面展示完整分析报告内容
- 支持 PDF 与 HTML 格式导出
- 报告内容：案件基本信息、主机基础信息、异常发现汇总、高危 IOC 命中、攻击时间线、持久化项清单、可疑外联清单、结论、处置建议

### 4.2 Agent 采集功能

Agent 为单文件可执行程序，运行后自动采集以下 16 大类数据并输出标准 JSON：

| 采集模块 | Windows 采集项 | Linux 采集项 |
|----------|---------------|--------------|
| 基础信息 | 主机名、IP、MAC、系统版本、补丁列表、时区、开机时间 | 主机名、IP、MAC、发行版、内核版本、时区、uptime |
| 用户信息 | 本地用户、管理员组、登录用户、最近登录 | /etc/passwd、sudoers、登录用户、last |
| 进程信息 | 进程名、PID、PPID、路径、命令行、父子进程树 | ps、/proc 进程树、命令行 |
| 服务信息 | Windows 服务（sc query） | systemd 服务列表 |
| 启动项 | 注册表 Run/RunOnce、计划任务、启动文件夹 | systemd、cron、rc.local、init.d |
| 网络信息 | netstat、路由、DNS、ARP、共享 | ss/netstat、路由、resolv.conf、ARP |
| 文件信息 | 敏感目录清单、最近修改文件、可疑扩展名 | 同左，路径适配 Linux |
| 注册表信息 | Run/RunOnce、SAM、系统配置、安全策略、RDP | N/A |
| 日志信息 | 系统/安全/应用/PowerShell/任务日志 | /var/log 系统日志、auth、syslog |
| 安全信息 | 杀毒软件、Defender、防火墙、已安装软件 | 防火墙（iptables/ufw）、已安装包（dpkg/rpm） |
| 浏览器痕迹 | Chrome/Edge/Firefox 历史、下载、密码、扩展 | 同左 |
| USB 痕迹 | 注册表 USBSTOR 接入记录 | /var/log USB 接入记录 |
| 远控痕迹 | RDP、AnyDesk、ToDesk、TeamViewer、向日葵 | SSH、VNC、远控软件 |
| 持久化痕迹 | WMI、计划任务、服务、注册表、启动项 | cron、systemd、init.d、bashrc |
| IOC 能力 | IP/域名/Hash/进程名/路径关键词匹配 | 同左 |
| 时间线信息 | 登录/进程/文件落地/服务创建/计划任务 | 同左 |

### 4.3 平台分析功能

导入 JSON 后，平台自动执行以下分析流程：

```
JSON 导入 → 数据解析与入库 → 主机画像生成 → 规则引擎分析 → 时间线构建 → 风险评级 → 处置建议生成 → 报告生成
```

| 分析模块 | 说明 |
|----------|------|
| 主机画像 | 汇总主机基础信息、用户画像、网络画像、服务画像、安全状态画像，结构化展示 |
| 异常进程识别 | 规则：无数字签名、可疑路径（Temp/Public/Downloads）、可疑命令行（编码/下载/反弹 shell）、已知恶意进程名匹配 |
| 异常外连识别 | 规则：连接已知恶意 IP/域名、非常规端口、可疑国家/地区 IP、外连频率异常 |
| 可疑启动项识别 | 规则：非系统路径启动项、可疑计划任务、伪装系统服务名 |
| 持久化痕迹识别 | 汇总 WMI/计划任务/服务/注册表/启动文件夹所有持久化点，标注风险等级 |
| 远控木马痕迹识别 | 规则库匹配已知远控木马特征（进程名、服务名、注册表键值、文件路径、网络特征） |
| 横向移动痕迹识别 | 结合安全日志（4624/4625/4672/4720/4732）与网络连接，识别 RDP/SMB/WMI/PsExec 横向移动 |
| 提权痕迹识别 | 安全日志提权事件、可疑 SYSTEM 计划任务、可疑服务权限 |
| 落地文件与驻留点识别 | 结合文件信息与持久化项，识别可疑路径落地文件与驻留点 |
| 攻击时间线 | 梳理所有带时间戳事件，按时间排序，支持按事件类型筛选 |
| 风险等级 | 综合异常项数量与严重程度，输出：高危/中危/低危/安全 |
| 处置建议 | 根据威胁类型给出针对性建议：隔离主机、终止进程、清除持久化项、加固配置等 |

### 4.4 报告功能

报告结构：

| 章节 | 内容 |
|------|------|
| 案件基本信息 | 案件编号、名称、类型、时间、描述 |
| 主机基础信息 | 主机名、IP、系统版本、采集时间等 |
| 异常发现汇总 | 各类异常项数量与风险等级分布 |
| 高危 IOC 命中 | 命中 IOC 详情（类型、值、来源、描述） |
| 攻击时间线 | 按时间排序的关键事件列表 |
| 持久化项清单 | 所有持久化项及其风险等级 |
| 可疑外联清单 | 可疑外连连接详情 |
| 结论 | 综合研判结论 |
| 处置建议 | 针对性处置建议列表 |

## 5. UI 设计概要

### 5.1 整体布局

- **布局结构**：左侧导航栏 + 顶部用户栏 + 右侧内容区
- **设计风格**：简洁专业，深色/浅色主题切换，以数据展示为核心
- **配色方案**：以深蓝/灰为主色调，风险等级用红/橙/黄/绿标识

### 5.2 主要页面

| 页面 | 布局描述 |
|------|----------|
| 登录页 | 居中登录卡片，Logo + 账号密码输入框 + 登录按钮 |
| 仪表盘 | 顶部统计卡片（案件数/主机数/高危主机数/最近采集）；下方最近案件列表与风险分布图表 |
| 案件管理 | 顶部搜索筛选栏 + 案件列表表格（编号/名称/类型/状态/主机数/风险/时间）；点击进入案件详情 |
| 案件详情 | 顶部案件信息卡片 + Tab 切换（主机列表/分析结果/报告）；主机列表可跳转主机详情 |

- 导入分析过程展示进度与状态反馈
- 关键操作（删除、导出）需二次确认

## 6. 非功能性需求

### 6.1 性能需求

| 指标 | 要求 |
|------|------|
| 平台启动时间 | ≤ 5 秒 |
| JSON 导入解析时间（10MB） | ≤ 10 秒 |
| 自动分析完成时间（单主机） | ≤ 30 秒 |
| 报告生成时间 | ≤ 10 秒 |
| 页面加载时间 | ≤ 2 秒 |
| Agent 采集时间（单主机） | ≤ 5 分钟 |
| Agent 文件大小 | Windows ≤ 15MB，Linux ≤ 15MB |
| 并发支持 | ≥ 5 个并发用户 |

### 6.2 安全需求

- 用户密码 bcrypt 加盐存储
- 所有 API 接口需鉴权，JWT Token 管理
- 上传 JSON 文件大小限制（≤ 100MB）与类型校验
- Agent 下载文件需校验完整性（SHA256 校验值展示）
- 数据库文件加密存储或文件系统级权限控制
- 操作日志记录关键操作（P2）
- 报告导出文件不包含敏感明文密码

### 6.3 兼容性需求

| 维度 | 要求 |
|------|------|
| 平台部署 OS | Windows 10/11、Windows Server 2016+、Ubuntu 20.04+、CentOS 7+、Debian 11+ |
| Agent 运行 OS | Windows 7/10/11、Windows Server 2008 R2+、主流 Linux 发行版 |
| 浏览器 | Chrome 90+、Edge 90+、Firefox 88+ |
| Python 运行环境 | Python 3.8+ |
| 数据库 | SQLite 3.35+ |
| 磁盘空间 | 平台 ≤ 500MB；数据存储按需扩展 |

### 6.4 可维护性需求

- 配置外置化：IOC 规则库、分析规则、敏感目录列表等通过配置文件管理，可热更新
- 日志记录：平台运行日志记录至本地文件，便于排查问题
- 数据库可备份：支持数据库文件复制备份
- 模块化设计：采集模块、分析模块、报告模块解耦，便于独立扩展

## 7. 待确认问题

| # | 问题 | 影响范围 | 建议 |
|---|------|----------|------|
| Q-1 | 用户认证是否需要多用户/角色权限管理？还是单用户即可？ | 用户认证模块 | 建议 P0 实现单用户，P1 支持多用户角色 |
| Q-2 | Agent 是否需要支持静默运行（无界面）？是否需要命令行参数控制采集范围？ | Agent 采集 | 建议支持 `-o output.json` 与 `--modules` 参数 |
| Q-3 | IOC 库来源：是否预置开源 IOC 库（如 MISP）？还是仅支持用户手动导入？ | IOC 能力 | 建议 P0 预置基础 IOC 库，P1 支持手动导入与在线查询 |
| Q-4 | 报告导出格式优先级：PDF 和 HTML 是否都需 P0 实现？是否还需要 Word/Excel？ | 报告导出 | 建议 P0 实现 PDF + HTML，P2 支持 Word |
| Q-5 | 是否需要支持 Agent 远程推送执行（如通过 SMB/SSH 远程下发）？ | Agent 部署 | 建议 P2 实现，P0 仅支持手动拷贝执行 |
| Q-6 | Linux Agent 采集是 P0 还是 P2？用户需求中提到「适配 Windows 和 Linux」，但采集项主要面向 Windows | Agent 采集 | 建议 Windows Agent 为 P0，Linux Agent 为 P2 逐步完善 |
| Q-7 | 数据存储中，原始 JSON 是否需要长期保留？还是解析入库后可删除？ | 数据存储 | 建议长期保留，便于追溯与重新分析 |
| Q-8 | 分析规则是否需要支持用户自定义规则（YARA/Sigma 等）？ | 自动分析 | 建议 P0 使用内置规则，P2 支持自定义规则 |
| Q-9 | 是否需要支持多语言（中英文）？ | UI 设计 | 建议 P0 中文，P2 支持英文 |
| Q-10 | 平台部署方式：Docker 容器化部署还是原生部署？是否两者都需支持？ | 部署方式 | 建议两者都支持，Docker 便于快速部署，原生部署便于离线场景 |
