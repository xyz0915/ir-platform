# 策略配置页筛选增强方案（应急专家视角）

## 一、现状问题分析

当前策略配置页（`/policies`）的筛选能力仅有：
- 规则分类（category）
- 严重度（severity）
- 规则名/关键词（keyword）

从应急响应（IR）实战角度看，存在以下盲区：

| 场景 | 当前痛点 | 风险 |
|---|---|---|
| 上线前快速核查 | 无法一眼看到“高危规则还有哪些没勾选” | 关键检测能力漏配，入侵发生时无告警 |
| 策略评审 | 没有按规则类型（正则/行为/攻击链等）的统计 | 无法判断行为基线与签名规则的配比是否合理 |
| 攻击链检测 | 无法单独筛选攻击链规则 | 攻击链覆盖缺口难以发现 |
| HITL 审批规则 | 无法筛选“需人工审批才会触发”的规则 | 误将高敏感规则当成自动检测规则启用 |
| 类别覆盖 | 分类下拉是硬编码，新增 category 不显示 | 新增规则无法被筛选，运营能力滞后 |
| 快速补漏 | 缺少一键补齐高危未选规则 | 应急时手动勾选效率低、易遗漏 |

## 二、本次已实现增强

已在前端 `PolicyConfigView.vue` 与后端 `/api/rules/selector` 落地以下能力：

### 2.1 新增筛选维度
- **规则类型**（rule_type）：正则 / 列表 / 行为分析 / 阈值 / 复合 / 攻击链 / 事件日志聚合 / 存在性检测
- **选择状态**：全部 / 已选 / 未选
- **HITL 审批**：仅显示 `condition._meta.requires_hitl=true` 的规则
- **攻击链**：仅显示 `rule_type=attack_chain` 的规则
- 分类下拉改为从实际规则动态推导，新增 category 自动出现

### 2.2 应急覆盖度看板
在筛选器上方新增覆盖度面板：
- **总览**：已选 / 全部 / 未选 + 进度条
- **严重度分布**：严重/高危/中危/低危 的 已选/总数，点击可快速筛选
- **类别覆盖**：按类别显示已选/总数，未覆盖完整的类别标红

### 2.3 一键补全高危未选
- 一键将所有 `critical`/`high` 且未选规则加入当前策略，并自动刷新列表

### 2.4 后端支持
- `/api/rules/selector` 新增 `rule_type` 查询参数，并放宽 `page_size` 上限至 500，支持策略页一次性拉取全量规则做前端筛选

## 三、对应急响应的价值

| 能力 | 应急场景 | 效果 |
|---|---|---|
| 未选筛选 | 新案件接入时快速确认策略是否遗漏关键规则 | 减少漏报 |
| 高危未选统计 |  red team/真实入侵后复盘策略配置 | 直观暴露盲区 |
| 规则类型分布 | 调整行为基线与签名规则的平衡 | 降低误报/漏报 |
| HITL 筛选 | 启用新策略前确认哪些规则需要人工审批 | 避免高敏感规则误启用 |
| 一键补全 | 紧急情况下快速启用全部高危规则 | 缩短 MTTD |

## 四、使用建议

1. **日常巡检**：打开策略页 → 查看覆盖度面板 → 对“高危”和“严重”为 0 或偏低的条目立即补齐。
2. **新规则上线**：使用“未选”+“高危”组合筛选，确认新增的高危规则是否已纳入策略。
3. **策略精简**：使用“已选”+ 分类/类型筛选，识别重复或低价值的规则并取消勾选。
4. **攻击链专项**：启用“攻击链”筛选，确保核心攻击链（如鱼叉附件→内存取→凭据转储）完整覆盖。
