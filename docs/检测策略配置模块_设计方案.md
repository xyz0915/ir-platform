# 检测策略配置模块 — 设计方案

> **设计视角**：一线应急响应专家
> **核心问题**：当前所有规则无差别全量运行 → 误报多、性能差、场景不可控

---

## 0. 应急专家分析：为什么要加策略

### 当前痛点

```
规则全量运行 → 在 Linux 主机上跑 Windows 注册表规则 → 误报
规则全量运行 → 所有规则都 check → 分析耗时翻倍
无法切换检测模式 → 日常巡检用"基线策略"，事件响应用"全面检测"
无法快速调整 → 发现某规则误报太多，只能去规则管理里禁用
```

### 策略能解决什么

| 场景 | 没有策略 | 有策略 |
|:-----|:---------|:-------|
| **日常巡检** | 全量规则，大量无关告警 | 用"基线策略"，只跑核心规则 |
| **应急响应** | 跟日常一样全量跑 | 切换"全面排查策略"，开启所有 + RAG |
| **POC/测试** | 只能用正式规则测试 | 复制一套策略，加测试规则，不影响生产 |
| **合规审计** | 找不到审计基线 | 预设 PCI-DSS / 等保2.0 专用策略 |
| **性能调优** | 跑完全部规则才知道耗时 | 轻量策略，只跑关键规则，秒级出结果 |

## 1. 核心概念

### 1.1 策略是什么

```
策略 = 一组检测规则的"套餐"
     + RAG 分析是否开启
     + 是否启用攻击链检测
     + 可以派生复制

全局唯一激活策略 → 分析引擎执行时按此策略过滤规则
```

### 1.2 工作流

```
日常 ←→ 应急切换
  
┌──────────────┐      ┌──────────────────┐
│ 基线策略      │      │ 全面排查策略      │
│ 规则: 50 条   │ ←──→ │ 规则: 200 条     │
│ RAG: 开启    │      │ RAG: 开启        │
│ 攻击链: 关闭 │      │ 攻击链: 开启      │
│ 场景: 日常    │      │ 场景: 事件应急   │
└──────────────┘      └──────────────────┘
        │                      │
        ▼                      ▼
    ┌──────────────────────────────┐
    │ 分析引擎 → 读取 active 策略   │
    │ → 只跑策略内的规则            │
    │ → 按策略配置执行 RAG         │
    │ → 按策略配置执行攻击链       │
    └──────────────────────────────┘
```

### 1.3 为什么限制唯一激活

```
如果同时激活多个策略：
  A 策略: 规则1,2,3    RAG: 开启
  B 策略: 规则4,5,6    RAG: 关闭
  → 分析时跑哪组规则含混不清
  → 策略=场景意图，只能有一个场景生效

唯一激活 = 明确当前检测意图
```

## 2. 数据库设计

```sql
-- ===== 检测策略主表 =====
CREATE TABLE IF NOT EXISTS detection_policies (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    name            TEXT NOT NULL,                              -- 策略名称
    description     TEXT DEFAULT '',                            -- 策略说明
    is_active       INTEGER DEFAULT 0,                         -- 是否激活 (全局唯一)
    enable_rag      INTEGER DEFAULT 0,                         -- 是否启用 RAG 语义分析
    enable_attack_chain INTEGER DEFAULT 0,                     -- 是否启用攻击链检测
    parent_id       INTEGER REFERENCES detection_policies(id), -- 派生来源策略ID
    rule_count      INTEGER DEFAULT 0,                         -- 规则数(缓存)
    tags            TEXT DEFAULT '',                            -- 标签逗号分隔
    created_at      TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at      TEXT NOT NULL DEFAULT (datetime('now'))
);

-- ===== 策略-规则关联表 =====
CREATE TABLE IF NOT EXISTS policy_rules (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    policy_id       INTEGER NOT NULL REFERENCES detection_policies(id) ON DELETE CASCADE,
    rule_id         INTEGER NOT NULL REFERENCES rules(id) ON DELETE CASCADE,
    enabled         INTEGER DEFAULT 1,
    created_at      TEXT NOT NULL DEFAULT (datetime('now')),
    UNIQUE(policy_id, rule_id)
);

CREATE INDEX idx_policy_active ON detection_policies(is_active);
CREATE INDEX idx_policy_rules_policy ON policy_rules(policy_id);
CREATE INDEX idx_policy_rules_rule ON policy_rules(rule_id);
```

## 3. API 设计

### 3.1 策略管理

```
GET    /api/policies                          # 策略列表
POST   /api/policies                          # 新建策略
GET    /api/policies/{id}                     # 策略详情（含规则列表）
PUT    /api/policies/{id}                     # 更新策略
DELETE /api/policies/{id}                     # 删除策略

POST   /api/policies/{id}/activate            # 激活策略（自动反激活其他）
POST   /api/policies/{id}/deactivate          # 停用策略
POST   /api/policies/{id}/duplicate           # 派生复制策略
```

### 3.2 策略-规则管理

```
GET    /api/policies/{id}/rules               # 策略内的规则列表
POST   /api/policies/{id}/rules               # 添加规则到策略 {rule_ids: [...]}
DELETE /api/policies/{id}/rules/{rule_id}     # 从策略移除规则
PUT    /api/policies/{id}/rules/batch         # 批量更新规则 {rule_ids: [...]}
```

### 3.3 规则筛选（给前端选择器用）

```
GET /api/rules/selector
  ?category=process                        # 筛选维度: 规则分类
  ?severity=critical,high                  # 筛选维度: 严重度
  ?platform=windows                        # 筛选维度: 平台
  ?keyword=web                             # 筛选维度: 关键词
  ?page=1
  &page_size=50
```

### 3.4 分析引擎集成

```
GET /api/policies/active                   # 获取当前激活策略（给分析引擎用）
  → {id, name, enable_rag, enable_attack_chain, rule_ids: [...]}
```

## 4. 分析引擎改造

### 4.1 执行流程

```python
def analyze(host_id: int) -> dict:
    # 1. 获取激活策略
    active_policy = DetectionPolicy.get_active()
    if not active_policy:
        # 无激活策略 → 默认全量检测（兼容旧行为）
        rules = Rule.get_all()
        rag_enabled = True
    else:
        # 2. 按策略过滤规则
        rules = active_policy.get_rules()
        rag_enabled = active_policy.enable_rag

    # 3. 只检测策略内的规则
    for rule in rules:
        result = RuleEngine.evaluate(rule)

    # 4. RAG 按策略开关
    if rag_enabled:
        knowledge_hits = KnowledgeRetriever.retrieve(...)
```

### 4.2 无策略时的降级行为

```
当前系统已有规则数据但没有策略表：
  首次访问策略页面时，自动创建"默认策略"并激活
  默认策略 = 全部规则 + RAG 开启
  保证升级后行为一致，不影响现有功能
```

```
│   ├── ○ Linux 基线
│   ├── ○ PCI-DSS 合规
│   └── [新建策略]
```

```
│ ☐ WEB-001  WebShell检测   严重  Cross   │

├────────────────────────────────────────┤
│ 已选 50 条  [保存选择]                 │
└────────────────────────────────────────┘
```

### 5.3 交互细节

| 操作 | 行为 |
|:-----|:-----|
| **点击激活** | 当前策略激活 → 其他所有策略自动停用 → 弹窗确认 |
| **点击派生** | 复制该策略的所有配置 + 规则 → 新策略名为"xxx(副本)" |
| **筛选规则** | 多维度交叉筛选，筛选结果不改变已选状态 |
| **已选计数** | 始终显示"已选 N 条/总共 M 条" |
| **切换策略** | 若未保存 → 弹窗提示"有未保存的修改，是否丢弃？" |
| **删除策略** | 已激活策略不可删除（需先停用） |
