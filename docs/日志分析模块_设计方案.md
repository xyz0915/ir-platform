# 日志分析模块 — 设计方案（应急专家视角 v2）

## 0. 设计原则

```
1. 时间线是灵魂 — 应急排查永远从"什么时间发生了什么"开始
2. 点击即跳转 — 看到 IP/用户/进程，点一下就能看到该维度的所有日志
3. 异常自动亮 — 暴破、横向移动、审计清除等高危模式自动标记
4. 事故可复原 — 按登录会话（Logon Session）重建攻击者操作时间线
```

---

## 1. 应急实战场景

### 场景 1：登录暴破排查

```
告警：某主机 4625 暴增
操作：日志分析中心 → 筛选 event_id=4625 → 按 source_ip 聚合
结果：发现 192.168.1.200 在 30 分钟内尝试 200 次登录
      → 点击 192.168.1.200 → 跳转到"该 IP 所有事件"
      → 发现该 IP 只在 07/12 22:00 - 22:03 有登录行为
      → 左侧时间线锁定攻击窗口
```

### 场景 2：进程溯源

```
发现：主机上有一个可疑进程 notepad.exe 启动了 cmd.exe
操作：日志分析中心 → 筛选 event_type=process_creation
      → 搜索 notepad.exe
      → 找到父进程 3556，点击父 PID 跳转
      → 发现父进程是 w3wp.exe（IIS），被注入了恶意 DLL
```

### 场景 3：横向移动追踪

```
发现：主机 A 上管理员登录 + 服务安装 + 新计划任务
操作：日志分析中心 → 筛选 event_id=4672（管理员登录）
      → 看到来源 IP 192.168.1.50（主机 B）
      → 切换筛选到 hostname=主机B
      → 发现主机 B 在相同时间段有 certutil 下载 + LSASS 转储
      → 完整攻击链：B→A 横向移动
```

## 2. 范式化格式（增强版）

### 2.1 统一事件结构

```json
{
  "id": 1,
  "host_id": 5,
  "hostname": "WEB-SRV-01",
  "log_source": "security",          // system | security | application | syslog
  "event_id": 4688,
  "event_type": "process_creation",
  "event_label": "进程创建",
  "mitre_attack": "T1059",          // ⭐ MITRE ATT&CK 编号
  "severity": "medium",              // ⭐ critical | high | medium | low | info
  "timestamp": "2026-07-12T09:30:00Z",
  "logon_session": "0x3E7",         // ⭐ 登录会话 ID（关联同一会话全部事件）

  // ⭐ 来源 & 目标（每条日志至少填一个，支持点击跳转）
  "source_ip": "192.168.1.50",
  "source_hostname": "",
  "target_ip": "",
  "target_hostname": "",

  // 用户 & 进程
  "user_name": "SYSTEM",
  "user_domain": "NT AUTHORITY",
  "process_name": "powershell.exe",
  "process_pid": 1234,
  "parent_process_name": "explorer.exe",
  "parent_process_pid": 888,
  "command_line": "powershell -enc SQBFAFgA",

  // 其他
  "object_name": "C:\\Users\\Public\\a.exe",
  "description": "新进程已创建。\n进程 ID: 1234\n父进程...",
  "raw_data": "..."                  // 完整原始描述（截取 500 字）
}
```

### 2.2 事件类型映射（应急专家分类）

#### 🚨 P0 — 急救必检（24h 内必须看的）

| Event ID | 事件类型 | 中文标签 | 严重度 | MITRE | 应急价值 |
|:--------:|:---------|:---------|:------:|:-----:|:---------|
| **1102** | `audit_log_cleared` | 🚨 审计日志清除 | **critical** | T1070 | **已失陷铁证** |
| **4688 + powershell** | `process_creation` | 进程创建(PS) | **high** | T1059 | 编码执行/无文件攻击 |
| **4688 + certutil** | `process_creation` | 进程创建(certutil) | **high** | T1105 | 下载器/后利用 |
| **4698** | `task_created` | 计划任务创建 | **high** | T1053 | 持久化驻留 |
| **7045** | `service_install` | 服务安装 | **high** | T1543 | 服务后门 |
| **4625 × N** | `failed_logon` | 登录失败暴增 | **high** | T1110 | 暴破攻击中 |

#### ⚠️ P1 — 深度排查

| Event ID | 事件类型 | 中文标签 | 严重度 | MITRE | 说明 |
|:--------:|:---------|:---------|:------:|:-----:|:-----|
| 4624 | `successful_logon` | 登录成功 | medium | T1078 | 关注非常规时间+非常用IP |
| 4672 | `admin_logon` | 管理员登录 | medium | T1078 | 特权账户使用 |
| 4648 | `explicit_logon` | 显式登录(RunAs) | medium | T1078 | 凭据传递 |
| 4720 | `user_created` | 用户创建 | high | T1136 | 影子账户 |
| 4732 | `user_added_to_group` | 用户加组(Admin) | high | T1098 | 权限维持 |
| 4719 | `audit_policy_change` | 审计策略变更 | high | T1562 | 防御绕过 |
| 5156 | `connection_allow` | 防火墙放行 | low | T1071 | 外连溯源 |
| 5927 | `service_install` | 驱动服务安装 | high | T1543 | 内核后门 |

| Event ID | 事件类型 | 中文标签 | 说明 |
|:--------:|:---------|:---------|:-----|
| 6005/6006 | `eventlog_state` | 日志服务启停 | 排查日志中断 |
| 6008 | `unexpected_shutdown` | 异常关机 | 可疑关机 |
| 7036 | `service_state_change` | 服务状态变更 | 服务启停监控 |

| — | `ssh_logon` | SSH 登录 | Linux |

### 3.2 应急专家交互设计

**1. 时间线视图（默认）**

| 功能 | 实现方式 |
|:-----|:---------|
| 水平时间轴 | ECharts 时间线 + dataZoom |
| 点代表事件 | 按严重度着色（红/橙/蓝/灰） |
| 聚合降噪 | 同一秒多条事件→显示数量角标 |
| 点击事件点 | 下方日志列表滚动到对应位置 |
| 异常标注 | 暴破/审计清除等 P0 事件自动标注 🚨 |
| 攻击窗口 | 鼠标拖拽选择时间段 → 日志列表自动过滤 |

**2. 预置分析视图**（一键切换，无需手动筛选）

| 视图 | 做了什么 |
|:-----|:---------|
| **暴破分析** | 自动聚合 4625 按 source_ip + user_name，展示 TOP 10 暴破源 IP + 时间窗口 |
| **横向移动** | 筛选 event_id in (4672, 4648, 5927, 5140) 按源 IP 聚合 |
| **进程溯源** | 筛选 event_type=process_creation，展示进程树（父→子→命令行） |
| **威胁告警** | severity=critical/high 的事件汇总，按主机分组 |
| **自定义** | 用户自由组合筛选条件，可保存为预设 |

**3. 点击即跳转（Pivot）**

| 点击位置 | 跳转到 |
|:---------|:-------|
| `source_ip` | 筛选该 IP 的所有事件（立即切换） |
| `user_name` | 筛选该用户的所有操作 |
| `process_name` | 筛选该进程所有事件 |
| `event_id` | 筛选该 Event ID 的全部事件 |
| `hostname` | 切换为该主机的全部日志 |
| `logon_session` | 该登录会话的全部活动（同一次登录的完整操作链） |

## 4. 实施路线（3 个 Phase）

### Phase 1 — 范式化引擎 + 入库（2 天）

| 任务 | 文件 | 说明 |
|:-----|:-----|:-----|
| `normalized_logs` 表 DDL | `database.py` | 建表 + 6 个索引 |
| `LogNormalizer` 类 | `app/analysis/log_normalizer.py` | Windows Event ID 映射(30+条) + Linux 正则(10+条) + MITRE + 安全标签 |
| `NormalizedLog` 模型 | `app/models/normalized_log.py` | batch_create / search / stats / pivot |
| 导入集成 | `import_service.py` | 导入 JSON 时自动范式化 |

### Phase 2 — API + 前端（2 天）

| 任务 | 说明 |
|:-----|:-----|
| `GET /api/logs/search` | 多维度检索 + 全文搜索 + 分页 |
| `GET /api/logs/stats/*` | 事件分布 / 时间线聚合 / 暴破统计 |
| `GET /api/logs/pivot` | 点击跳转关联查询 |
| `GET /api/hosts/{id}/logs` | 主机关联日志 |
| **LogAnalysisView.vue** | 三段式布局 + 时间线 + 预置视图 + 点击跳转 + 详情抽屉 |
| HostDetailView 日志 Tab | 内嵌日志列表 + 快速筛选 |

### Phase 3 — 增强（1 天）

| 任务 | 说明 |
|:-----|:-----|
| 暴破检测规则 | 5 分钟内 4625 > 10 次 → 自动告警 |
| 行为基线 | 统计每台主机历史事件分布，偏离基线自动标记 |
| 日志导出 PDF/CSV | 调查结果一键导出 |
| 关联 CASE 系统 | 选中可疑日志直接标记到案件时间线 |
