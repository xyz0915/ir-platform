# 分析中心事件详情页三栏布局重构 — 产品需求文档（PRD）

## 1. 项目信息

- **项目名称**: event_detail_redesign
- **语言**: 中文
- **前端技术栈**: Vue 3 + Element Plus + Pinia
- **后端技术栈**: FastAPI + SQLite
- **原始需求**: 将分析中心（Analysis Center）事件详情页从当前的两列/单列折叠布局重构为三栏布局，提升攻击链可追溯性、AI 研判可见性和整体分析效率。

---

## 2. 产品定义

### 2.1 产品目标

1. **提升攻击链可追溯性**：通过左侧攻击链时间线，让分析师一眼看清事件在 MITRE ATT&CK 全生命周期中的位置，快速理解攻击上下文。
2. **强化 AI 辅助效率**：将 AI 研判、IOC 威胁指标、处置建议集中到右侧常驻面板，减少滚动查找，加速决策闭环。
3. **优化信息消费密度**：通过三栏固定宽度布局，将事件详情（中栏）与辅助信息（左/右栏）解耦，避免信息散落在折叠面板中。

### 2.2 用户故事

| # | 用户故事 |
|---|---------|
| US-1 | **作为** 安全分析师，**我想** 在事件详情页左侧看到按 MITRE ATT&CK 阶段组织的攻击链时间线，**以便** 快速理解当前事件在攻击全生命周期中的位置和前后关联。 |
| US-2 | **作为** 安全分析师，**我想** 在右侧固定面板中集中查看 AI 研判结论、IOC 威胁指标、关联告警和处置建议，**以便** 无需滚动页面即可完成大部分研判决策。 |
| US-3 | **作为** 安全分析师，**我想** 在中栏按"事件概要 → 命中规则 → 进程链树 → 证据详情 → 关联事件"的顺序浏览事件完整详情，**以便** 逻辑清晰地逐层深入分析。 |
| US-4 | **作为** 安全团队负责人，**我想** 在顶部决策栏中一目了然地看到严重度、风险评分、ATT&CK 标签和当前状态，并快速执行状态流转操作，**以便** 提升事件处置效率。 |

### 3.2 顶部区域

#### 导航栏
- **返回按钮**: 返回分析中心列表页
- **案件信息**: 显示所属案件名称/编号，可点击跳转案件详情
- **事件元信息**: 事件 ID（简写）、时间戳、主机名、采集器来源

#### 决策操作栏
- **严重度徽章**: critical/high/medium/low/info，带颜色标识
- **风险评分**: 0-100 数值，按颜色分段（>=70 红, >=50 橙, >=30 蓝）
- **ATT&CK 标签**: 显示当前事件攻击阶段（如"执行"、"C2"）
- **状态标签**: 待处理/分诊中/调查中/已解决/已误报
- **状态流转按钮**: 根据当前状态显示可用操作按钮（分诊 → 调查 → 解决 / 误报 / 重开）
- **深度调查按钮**: 跳转 Agent 编排页面

### 3.3 左栏 — 攻击链时间线（280px）

- **标题**: "攻击链时间线"
- **内容**: 按 MITRE ATT&CK 阶段从上到下排列
- **每阶段显示**:
  - 阶段图标 + 中文标签
  - 该阶段事件数量（徽章）
  - 关键活动摘要（最近一条事件的简述）
  - 当前事件所在阶段高亮标记
- **交互**:
  - 点击阶段可展开查看该阶段的事件列表
  - 展开后点击事件可跳转到该事件详情
  - 支持折叠/展开
- **数据来源**: `GET /api/analysis/events/timeline`（按 attack_chain_id 分组）+ 前端本地按 `attack_stage` 聚合

### 3.4 中栏 — 事件详情（flex: 1）

#### ① 事件概要卡片
- 事件类型（中文标签）、时间戳、主机名（可点击筛选）
- 采集器来源
- 攻击链 ID
- 同类事件频率统计（首次/最近/总次数/影响主机数）
- 父进程、文件哈希（含复制/VT 打开）、签名状态（按事件类型显示）

#### ② 命中规则列表
- 每条规则：名称、严重度徽章、描述、置信度
- 无匹配规则时显示"无匹配规则（基于模型推断）"
- 支持查看更多规则（折叠展开）

#### ③ 进程链树
- 树形结构展示进程父子关系
- 当前进程高亮
- 每个节点：进程名、PID、命令行（截断）
- 深度缩进表示层级

#### ④ 证据详情
- 范式化视图与原始数据视图切换
- 范式化视图：按字段展示关键证据字段
- 原始视图：JSON 原始数据 + 数据来源标记
- 自适应主体（按事件类型展示进程主体/网络主体/持久化落点）

#### ⑤ 关联事件列表
- 显示事件 ID（简写）
- 事件类型、时间、严重度
- 点击可查看该关联事件

### 3.5 右栏 — AI 研判 + 辅助信息（320px）

#### ① AI 研判面板
- **AI 结论标签**: AI 优先推荐 / 可疑待复核 / 误报 / 良性
- **置信度**: 百分比数值，>=80% 红色/高置信，>=60% 橙色/中等
- **MITRE 技术**: T-code 标签（如 T1059）
- **攻击类型**: 如"勒索软件"、"横向移动"
- **建议动作**: 隔离主机 / 结束进程 / 封锁 IP / 人工复核
- **研判理由**: 文字说明
- **AI 分析原文**: 可展开查看完整分析文本（如存在）

#### ② IOC 威胁指标
- 按类型分组：IP 地址、SHA256、域名、MD5、文件路径
- 每个 IOC 可点击复制
- 哈希值支持一键打开 VirusTotal

#### ③ 关联告警
- 关联告警列表（如存在）
- 告警名称、时间、严重度

#### ④ 处置建议
- 根据事件严重度动态生成建议文案
- Critical/High: 建议隔离主机、终止进程、收集取证数据
- Medium: 建议确认是否为正常业务操作
- Low/Info: 建议归档记录

#### ⑤ 主机概况统计
- 24h 事件总数
- 规则命中数
- 活跃告警数
- 上次处置记录（时间、操作人、备注）

#### ⑥ 处置记录（置于右栏底部）
- 处置记录列表（操作人、动作、备注、时间）
- 快速添加备注输入框 + 发送按钮

## 4. 数据需求

### 4.1 现有 API 端点（可直接复用）

| 端点 | 用途 | 对应栏位 |
|------|------|---------|
| `GET /api/analysis/events/{event_id}` | 事件基础详情 + IOC 提取 + 同类频率 | 中栏①、右栏② |
| `GET /api/analysis/events/{event_id}/display` | 前端展示投影（必填/辅助字段 + 证据双视图） | 中栏②④ |
| `GET /api/analysis/events/{event_id}/process-tree` | 进程树 | 中栏③ |
| `GET /api/analysis/events/{event_id}/network-graph` | 网络连接图 | 中栏④ 上下文 |
| `GET /api/analysis/events/{event_id}/context` | 时间线上下文（前后 N 分钟） | 左栏辅助 |
| `GET /api/analysis/events/{event_id}/host-stats` | 主机 24h 统计 | 右栏⑤ |
| `GET /api/analysis/events/{event_id}/impact` | 影响范围 | 右栏⑤ |
| `GET /api/analysis/events/{event_id}/dispositions` | 处置记录列表 | 右栏⑥ |
| `POST /api/analysis/events/{event_id}/dispositions` | 添加处置记录 | 右栏⑥ |
| `GET /api/analysis/events/{event_id}/related` | 关联事件列表 | 中栏⑤ |
| `GET /api/analysis/events/timeline` | 攻击链时间线 | 左栏 |
| `GET /api/analysis/events/stats` | 统计卡片 | 右栏⑤ |
| `PATCH /api/analysis/events/{event_id}/status` | 状态变更 | 顶部决策栏 |

### 4.2 新增/改造数据需求

| 需求 | 说明 | 优先级 |
|------|------|--------|
| 攻击链按 attack_stage 聚合 | 前端从 `timeline` API 返回数据中按 `attack_stage` 字段做二次聚合（无需后端改造） | P0 |
| 事件 AI 研判数据 | 已存在于 `event.ai_verdict` (JSON) 和 `event.ai_analysis` 字段，按 label/confidence/action 解析展示 | P0 |
| 关联告警数据 | 需确认 `related_events` 字段是否包含告警 ID，或需新增关联告警查询端点 | P1 |
| 主机概况 last_disposition | 已在 `hostStats` 中返回，含上次处置记录 | P0 |

## 8. 实施建议

1. **渐进式改造**：先用新组件 `ThreeColumnLayout.vue` 包裹现有内容，逐步替换为新的子组件，避免大范围重构。
2. **按 P0 → P1 顺序交付**：先确保三栏布局和核心数据加载正常，再逐步添加交互细节和增强功能。
3. **复用现有 Store**：`useAnalysisStore` 已包含 `fetchEventDetailEnhanced()` 和 `fetchEventDisplay()`，可直接在新组件中调用。
4. **后端无重大改造**：现有 API 已满足绝大部分数据需求，无需新增端点。
5. **测试要点**：三栏布局在不同屏幕宽度下的表现、左右栏独立滚动、状态流转交互流程、数据加载异常处理。
