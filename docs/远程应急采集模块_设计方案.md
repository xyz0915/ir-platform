# 🚀 远程应急采集模块设计方案

> **视角**：应急响应专家
> **目标**：从研判平台直接 SSH 登录远程主机采集数据，自动入案件库并标注"远程采集"
> **核心理念**：黄金时间内，分析人员无需等待现场人员操作，一键远程采集

---

## 一、用户故事

**作为** 应急响应分析人员
**我希望** 在案件详情页直接点击"远程采集"→ 输入 IP + 凭据 → 自动 SSH 登录并执行 Agent 采集
**以便于** 在黄金应急时间内获取远程主机的取证数据，无需等待现场人员手动操作

**流程**：
```
案件详情 → 点击"远程采集" → 填写目标 IP/端口/凭据 → 选择采集范围 → 执行
  → 平台 SSH 登录 → 推送 agent.py → 执行采集 → 拉取 JSON → 自动导入
  → 创建主机记录 → 标注"远程采集" → 触发分析 → 跳转主机详情
```

## 三、数据模型

### 3.1 采集任务表 `remote_tasks`

| `result_summary` | TEXT | 采集结果摘要 JSON |
| `error_message` | TEXT | 失败原因 |
| `is_remote_collect` | BOOLEAN | 固定为 `true`，标注远程采集 |
| `created_by` | TEXT | 发起人 |
| `created_at` | TEXT | 创建时间 |
| `started_at` | TEXT | 开始执行时间 |
| `completed_at` | TEXT | 完成时间 |

### 3.2 hosts 表扩展字段

现有 `hosts` 表只需新增一个字段即可：

| 字段 | 类型 | 说明 |
|------|------|------|
| `collect_source` | TEXT | `"manual"`（手动导入） / `"remote"`（远程采集） / `"agent"`（Agent 下载） |

这样前端可以在主机列表和详情页标注"远程采集"来源。

### 4.2 认证凭据管理

**安全设计方案**：
1. 凭据**不落库**，仅存在于内存中的采集任务对象中
2. 任务完成后释放凭据
3. 支持密码认证和 SSH Key 认证
4. 可选：从平台已有的凭据管理中读取（当前无此功能，留扩展点）

**支持的主机指纹验证**：
- 首次连接时验证主机公钥指纹（显示给用户确认）
- 支持跳过指纹验证（应急场景可配置）

### 4.4 远程采集编排

```python
class RemoteCollector:
    """远程采集编排器."""

    # 默认采集模块（应急场景必采项）
    DEFAULT_MODULES = [
        "system_info",    # 系统信息：主机名、OS、IP
        "users",          # 用户账户
        "processes",      # 进程列表（含命令行、网络连接）
        "network",        # 网络连接
        "services",       # 系统服务
        "startup_items",  # 启动项
        "persistence",    # 持久化（cron/systemd/SSH key）
        "files",          # 文件系统变更
        "security",       # 安全产品状态
        "logs",           # 系统日志
        "ioc",            # IOC 指标匹配
        "linux_baseline", # Linux 基线检查
    ]

    # 深度采集（P2 可选）
    DEEP_MODULES = DEFAULT_MODULES + [
        "webshells",      # WebShell 扫描
        "memory_shells",  # 内存 Shell 检测（Linux 下受限）
        "process_events", # 进程事件溯源
    ]

    async def run(self, task_id: int) -> dict:
        """执行完整的远程采集流程."""
        
        # 1. 读取任务配置
        task = RemoteTask.get_by_id(task_id)
        
        # 2. SSH 连接
        connector = SshConnector()
        ok = await connector.connect(task_id, task.target_ip, ...)
        
        # 3. 创建远程临时目录
        remote_dir = f"/tmp/ir_collect_{uuid7()}"
        await connector.execute(task_id, f"mkdir -p {remote_dir}")
        update_progress(task_id, 10, "已连接，准备采集环境")
        
        # 4. 推送 agent 源码（无需 pip install，纯标准库）
        agent_files = ["agent.py", "collectors/", "utils/"]
        for f in agent_files:
            await connector.upload_file(task_id, f, f"{remote_dir}/{f}")
        update_progress(task_id, 25, "Agent 已推送至远程主机")
        
        # 5. 执行采集
        modules = ",".join(task.collect_modules or self.DEFAULT_MODULES)
        cmd = f"cd {remote_dir} && python3 agent.py --collect {modules} --output-dir {remote_dir}"
        stdout, stderr = await connector.execute(task_id, cmd, timeout=600)
        update_progress(task_id, 70, "采集执行中")
        
        # 6. 自动发现生成的 JSON 文件
        find_cmd = f"ls {remote_dir}/*.json 2>/dev/null | head -1"
        json_path, _ = await connector.execute(task_id, find_cmd)
        json_path = json_path.strip()
        
        # 7. 拉取 JSON 到本地临时目录
        local_path = f"/tmp/remote_collect/{task_id}.json"
        await connector.download_file(task_id, json_path, local_path)
        update_progress(task_id, 85, "数据回传完成")
        
        # 8. 自动导入
        with open(local_path, "rb") as f:
            file_content = f.read()
        result = ImportService.import_json(
            host_id=None,  # 自动创建新主机
            file_content=file_content, 
            file_name=f"remote_{task.target_ip}.json",
            collect_source="remote",
            case_id=task.case_id,
        )
        update_progress(task_id, 95, "数据已导入案件库")
        
        # 9. 更新任务完成状态
        host_id = result["host_id"]
        RemoteTask.complete(task_id, host_id=host_id, ...)
        
        return {"host_id": host_id, "result": result}
```

### 4.5 自动导入集成

在 `ImportService.import_json()` 中增加一个可选参数：

```python
@staticmethod
def import_json(
    host_id: Optional[int] = None,
    file_content: bytes = None,
    file_name: str = "",
    collect_source: str = "manual",  # ← 新增：标记采集来源
    case_id: Optional[int] = None,   # ← 新增：指定所属案件
) -> dict:
```

逻辑调整：
- 如果 `host_id` 为 `None` 且指定了 `case_id`：**自动创建主机**
  ```python
  if host_id is None and case_id:
      # 从 JSON 中解析主机名
      raw_data = json.loads(file_content)
      hostname = raw_data.get("metadata", {}).get("hostname", f"remote_{target_ip}")
      host = Host.create(
          case_id=case_id,
          hostname=hostname,
          ip_address=target_ip,
          collect_source="remote",
      )
      host_id = host["id"]
  ```
- 保存 `collect_source` 字段到 `hosts` 表
- 后续分析结果中透传此字段，前端展示"远程采集"标签

## 六、安全设计

| 风险 | 缓解措施 |
|------|---------|
| 凭据泄露 | 凭据仅存内存，不落库；任务完成后立即释放；SSH Key 优先密码 |
| 中间人攻击 | 默认验证主机指纹；应急场景可配置跳过 |
| 权限过大 | 限制使用非 root 用户（sudo 提权可选）；命令执行白名单 |
| 横向移动风险 | 平台应限制可访问的目标网段；记录全部操作审计日志 |
| 采集数据泄露 | 传输加密（SSH 本身加密）；临时文件采集后自动清理 |
| 并发连接数 | 限制单用户最多 5 个并发远程采集任务 |

**凭据生命周期**：
```
用户输入 → 内存存储 → SSH 连接 → 任务完成/失败 → 内存释放
  ↑                      ↓
  └── 永不落库 ──────────┘
```

## 十、实施建议

| 阶段 | 内容 | 工作量 | 收益 |
|------|------|--------|------|
| **Phase 1（MVP）** | SSH 密码认证 + 默认采集模块 + auto-import + 前端弹窗 | **2-3 天** | 🔥 最快的应急响应路径 |
| **Phase 2** | SSH Key 认证 + 自定义采集模块 + SSE 进度推送 | **1 天** | 更灵活的认证方式 |
| **Phase 3** | WinRM 支持（Windows 远程采集）+ 并发限制 + 审计日志 | **2 天** | 覆盖 Windows 场景 |
| **Phase 4** | 凭据管理（加密存储/复用）+ 批量采集 + 采集模板 | **2 天** | 效率提升 |

**建议优先做 Phase 1**：密码认证 + Linux SSH + 默认模块 + 自动导入，已经能覆盖 80% 的应急场景。远程采集完成后直接跳转主机详情页触发分析，整个流程不超过 30 秒。
