# 智能体编排详情页 — 产品需求文档 (PRD)

> **项目**: IR 安全事件响应平台  
> **版本**: v1.0  
> **状态**: 初稿  
> **创建日期**: 2025-07-17  
> **编程语言**: Vue 3 + Element Plus（前端）/ FastAPI + SQLite（后端）

---

## 1. 产品目标

| # | 目标 | 说明 |
|---|------|------|
| G1 | **实时可见性** | 分析员查看编排调查过程时，能实时看到每个 Agent 的执行流水线——谁在做什么、找到什么、当前状态如何，不再是一个黑盒 |
| G2 | **证据链路可视化** | 右栏证据图谱让分析员一目了然看到事件关联实体之间的证据链路，发现隐藏的攻击路径和关联关系 |
| G3 | **全流程闭环** | P0/P1/P2 全部完成后，形成"实时流 + 证据网 + 交互探索"的完整调查体验，覆盖从查看到深入分析的完整工作流 |

## 2. 用户故事

| ID | 用户故事 |
|----|----------|
| US-01 | **作为**安全分析员，**我希望**在点击编排运行时立即看到 SSE 实时推送的 Agent 执行步骤，**以便**第一时间掌握调查进度，无需等待全部完成 |
| US-02 | **作为**安全分析员，**我希望**在调查过程中看到证据图谱随着 SSE 事件实时新增节点和连线，**以便**直观理解实体间的关联关系 |
| US-03 | **作为**安全分析员，**我希望**点击图谱节点能联动跳转到左栏对应证据步骤，**以便**快速定位产生该证据的上下文 |

## 3. 需求池

### P0 — 核心（Must Have）

| ID | 需求 | 描述 | 验收标准 |
|----|------|------|----------|
| P0-01 | SSE 流式端点 | 后端新增 `/agents/runs/{run_id}/stream` 端点，每次 `dispatch()` 完成一个步骤后 push 增量事件 | 每个步骤完成后 500ms 内推送；包含 step_id、agent、stage、status、output、evidence、timestamp |
| P0-02 | 双栏详情视图 | 替换现有 el-drawer，新建全屏双栏详情页；顶部 tab 切换"调查过程" / "调查结论" | 左栏占 55-60%，右栏占 40-45%；tab 切换时保留各自状态 |
| P0-03 | 左栏 SSE 订阅 | 前端建立 EventSource 连接，每收到一个增量事件 append 一个步骤卡片 | 卡片包含：Agent 名称、阶段名称、耗时、状态图标、输出内容（Markdown 渲染） |
| P0-04 | 运行中状态动画 | 正在执行的 Agent 步骤卡片显示转圈/脉冲动画 | 动画流畅，不阻塞其他卡片渲染 |
| P0-05 | 错误状态标记 | 出错的步骤显示 ✗ 标记，并用红色边框高亮 | 错误信息可展开查看详情 |

### P1 — 增强（Should Have）

| ID | 需求 | 描述 | 验收标准 |
|----|------|------|----------|
| P1-01 | 证据图谱（网状多向连线） | 右栏用原生 SVG 实现网状多向连线布局，节点代表实体，边代表关联关系 | 节点类型 ≥5 种；连线方向正确；不使用第三方图库 |

| P1-04 | 节点实时新增 | 图谱节点随 SSE 事件动态新增，带淡入/位移微动画 | 新节点出现时有 300ms 过渡动画 |
| P1-05 | 数据源解析 | 节点数据来自 `agent_run_steps.evidence_json` 中的 `data_sources` 和 `evidence` 字段 | 自动去重；相同实体合并为同一节点 |

#### SSE 连接管理

- 前端使用 `EventSource` 建立连接
- 连接失败时自动重连，重连间隔指数退避（1s → 2s → 4s → 8s → 16s，上限 30s）
- 底部状态栏显示 🟢 SSE 连接中 / 🔴 SSE 已断开
- 复用现有的 `alert_ws_manager` 或 `notification_service` 做连接管理

### 5.2 图谱数据结构

#### 节点 Schema

```typescript
interface GraphNode {
  id: string;            // 唯一标识，如 "host_1"
  type: 'host' | 'url' | 'action' | 'file' | 'process';
  label: string;         // 显示名称
  properties: Record<string, any>;  // 扩展属性
  x?: number;            // 布局位置（由布局算法计算）
  y?: number;
}
```

#### 边 Schema

```typescript
interface GraphEdge {
  id: string;            // 唯一标识 "edge_1"
  source: string;        // 源节点 ID
  target: string;        // 目标节点 ID
  relation: string;      // 关系类型："连接" | "启动" | "包含" | "关联"
  description?: string;  // 关系描述
  directed: boolean;     // 是否有向
}
```

#### 图谱布局算法

- 使用**力导向布局**（简单实现，不依赖第三方库）
- 节点间斥力：使节点均匀分布
- 边的引力：将相连节点拉近
- 边界约束：防止节点溢出画布
- 布局在每次新增节点时增量计算（只调整受影响区域）

#### 颜色映射

| 节点类型 | 颜色 | Hex |
|----------|------|-----|
| 主机 | 红色 | `#E74C3C` |
| 资源/URL | 蓝色 | `#3498DB` |
| 执行动作 | 橙色 | `#F39C12` |
| 文件 | 绿色 | `#2ECC71` |
| 进程 | 紫色 | `#9B59B6` |

### 5.3 前后端数据流图

```
┌──────────┐     SSE Push (step_update / step_completed)     ┌──────────────┐
│  FastAPI  │ ──────────────────────────────────────────────▶ │  Vue 3 前端   │
│  Backend  │                                                │              │
│           │  1. dispatch() 执行步骤                         │  EventSource │
│           │  2. 完成后 push step_update                    │  接收事件    │
│           │  3. 左栏卡片 append + 右栏图谱新增节点         │              │
│           │                                                │  ← 双栏渲染  │
│           │  evidence_json.data_sources ────▶ 图谱节点      │              │
│           │  evidence_json.evidence ────────▶ 图谱边        │              │
└──────────┘                                                └──────────────┘
```

## 6. 技术约束

| 项 | 说明 |
|----|------|
| 前端框架 | Vue 3 + Element Plus（现有） |
| 后端框架 | FastAPI + SQLite（现有） |

## 8. 测试验证要点
