# 智能体编排管理 · 前端功能预览（原型）PRD

> 文档类型：简单 PRD（功能预览 / 原型）
> 产出角色：产品经理（Alice）
> 需求依据：《智能体编排管理 — 优化后方案》（单底座策略 · Orchestrator 唯一执行引擎）
> 预览性质：用 mock 数据驱动，**不接真实后端**，仅用于用户审核 UI 与交互

---

## 1. 项目信息

- **Language**：简体中文
- **Programming Language**：Vite + React + MUI + Tailwind CSS（预览原型独立栈；与线上 Vue3/ElementPlus 解耦，仅对齐视觉风格）
- **Project Name**：`agent_orchestration_preview`
- **原始需求复述**：基于《智能体编排管理 — 优化后方案》（单底座：Orchestrator 唯一引擎 + PipelineEngine 降级为配置/DAG 定义层；架构组件含 ToolRegistry/MemoryLayer/Planner-Reflector/统一 HITL/Guardrails/AgentLLM/Observability/DAG 配置层/版本管理；功能集 F1–F14，路线 M0–M4，M0 为硬前置），设计并实现一个**前端 Web 功能预览页面**，需覆盖：①核心功能模块交互界面 ②页面导航结构 ③数据展示区域 ④用户操作流程可视化 ⑤响应式布局 ⑥体现方案视觉风格与交互逻辑。

---

## 2. 产品目标

本预览面向 **SOC 主管、安全分析师、编排管理员** 三类角色，将《优化后方案》中抽象的"单底座 + 架构组件 + F1–F14"能力，转化为**可点击、可浏览、可感受**的前端界面原型。核心价值是让用户在上线前就**直观确认编排管理的产品结构是否成立、交互是否符合 SecOps 工作习惯、M0（修空壳 + 无状态化 + SSE/HITL 统一）相关模块是否优先呈现**。

预览不验证后端能力真实性（全部 mock 驱动），但必须**忠实还原方案定义的信息架构、优先级与视觉语言**：以暗色 SecOps 风格为主、强调可观测性与"高风险动作必经护栏/HITL"的安全主线，使评审能聚焦"该不该这么做"而非"能不能跑起来"。

## 3. 用户故事

### 安全分析师（Analyst）
- 作为安全分析师，我要在**概览 Dashboard** 一眼看到当前运行中智能体、成功率与待我审核的 HITL 任务，以便优先处理高风险动作。
- 作为安全分析师，我要在**人工审核台**收到待审任务时，查看完整上下文（触发智能体、动作、护栏校验结果）后做出批准/拒绝，避免误操作破坏性指令。
- 作为安全分析师，我要在**可观测性**时间线里回看某次运行的 step/trace/日志，定位智能体跑飞或工具失败的原因。

### SOC 主管（SOC Lead）
- 作为 SOC 主管，我要在 Dashboard 查看团队整体的运行成功率、护栏拦截数与近期运行趋势，用于向上汇报与容量决策。
- 作为 SOC 主管，我要在**护栏与安全**页面确认 action 白名单与高危动作确认/回滚策略已就位，确保 F8（P0）上线前提被满足。
- 作为 SOC 主管，我希望通过**流水线编排 DAG 画布**预览，理解编排如何"所见即所得"，便于向业务方解释自动化链路。

### 编排管理员（Orchestration Admin）
- 作为编排管理员，我要在**智能体管理**中浏览内置 + 自定义 Agent 列表，并能查看/配置某个 Agent 的工具、数据来源与依赖。
- 作为编排管理员，我要在**工具与 MCP** 页面确认已注册工具、MCP 服务器在线状态，理解 F1 工具生态的接入情况。
- 作为编排管理员，我要在**设置**中配置多模型（F10）与切换无状态部署开关（F14），预览 M0/M3 相关能力入口。

## 5. UI 设计稿描述（供架构师落地）

### 5.1 导航结构
- **布局**：左侧固定侧边栏（可折叠）+ 顶部 AppBar（全局搜索 / 运行态指示 / 用户菜单 / 主题切换）。
- **模块菜单项与层级**：

```
AppBar（顶栏）
 ├─ 平台名 + 运行态指示灯（绿/橙/红）
 ├─ 全局搜索（智能体/运行/工具）
 ├─ 待审 HITL 角标（数字）
 ├─ 主题切换（暗/亮）
 └─ 用户菜单

Sidebar（侧边栏，一级菜单）
 ├─ 概览 Dashboard        (M1, P0)
 ├─ 智能体管理            (M2, P0)
 ├─ 流水线编排            (M3, P1)
 ├─ 工具与 MCP            (M4, P1)
 ├─ 记忆与 RAG            (M5, P2)
 ├─ 人工审核台            (M6, P0)  ← 待审数角标
 ├─ 护栏与安全            (M7, P0)
 ├─ 可观测性              (M8, P1)
 └─ 设置                  (M9, P1)
```

### 5.2 视觉风格方向（SecOps）
- **主题**：暗色为主（默认），可一键切换亮色；整体克制、信息密度高、强调状态可辨。
- **色彩 Token 方向**（建议 MUI `theme.palette` 扩展）：
  - `primary`（主色/品牌）：深蓝青 `#3B82F6` 系，沉稳不刺眼
  - `secondary`/`accent`（强调）：青绿 `#10B981` 用于"可交互/激活"
  - `success`（成功绿）：`#22C55E`；`warning`（警告橙）：`#F59E0B`；`danger`（危险红）：`#EF4444`；`info`（信息蓝）：`#3B82F6`
  - 背景层：暗色底 `#0F172A` / 卡片 `#1E293B` / 分割线 `#334155`
- **形态**：圆角 `8px`（卡片）、间距 8 倍数（MUI `spacing`）、卡片化容器、微阴影；状态用色块/徽标（chip）而非纯文字。
- **组件库**：MUI（Material UI v5）+ Tailwind 原子类辅助布局；图表用 MUI X Charts / Recharts mock。
- **字体**：等宽用于 trace/日志，无衬线用于正文。

### 5.3 关键用户操作流程（可视化呈现）
> 以下流程在预览中须以**步骤条（Stepper）+ 状态组件 + 轻动画**呈现，让评审"看见"操作链路。

**流程① 创建自定义 Agent 并配置工具 → 保存**
`智能体管理` → 点击「新建自定义 Agent」→ 填写 display_name / 数据来源 / 依赖 → 从 `ToolRegistry` 勾选工具（schema 预览）→ 「保存」→ 卡片出现于列表（mock 落库提示）。

**流程② DAG 画布拖拽节点连线编排流水线 → 校验 → 运行**
`流水线编排` → 从节点面板拖入「调查 / 取证 / 处置」步骤节点 → 连线定义流转 → 点「校验」（mock 校验 DAG 是否闭环、是否含护栏节点）→ 「运行」→ 画布节点按 step 顺序高亮 + 顶部 SSE 流式进度（mock）。

**流程③ HITL 审核台收到待审 → 查看上下文 → 护栏校验 → 批准/拒绝**
`人工审核台` → 队列出现待审任务（角标+1）→ 展开上下文（触发智能体 / 拟执行 action / 影响范围）→ 显示 `Guardrails` 校验结果（白名单命中 / 高危确认 required）→ 点「批准」（联动运行继续）或「拒绝」（写回拒绝原因，运行终止）。

### 5.4 响应式布局
- **桌面（≥1280px）**：侧边栏常驻展开 + 主内容多列卡片网格。
- **平板（768–1279px）**：侧边栏可折叠为图标栏，主内容两列。
- **移动（<768px）**：侧边栏收为抽屉（汉堡菜单），主内容单列纵向堆叠，DAG 画布转为只读缩略 + 节点列表。

## 6. 待确认问题

1. **范围聚焦**：预览是**聚焦 M0 相关模块**（Dashboard / 智能体管理 / 人工审核台 / 护栏 / 设置）做深，还是**覆盖全 F1–F14 九模块**做广度？建议首版以 M0 + 安全主线（M1/M2/M6/M7/M9）优先，其余 M3/M4/M5/M8 做静态占位。
2. **默认主题**：是否**默认暗色**（SecOps 惯例）？还是默认亮色？需拍板以定首屏。
3. **登录态模拟**：预览是否需要模拟登录/角色切换（分析师/主管/管理员视图差异），还是直接进入、用顶部角色切换器即可？
4. **数据真实性**：mock 数据是否按方案中的真实字段语义（如 `AgentRun`/`hitl_approval`/`step_*`）构造，以便在真实后端就绪后平滑替换？建议是。
